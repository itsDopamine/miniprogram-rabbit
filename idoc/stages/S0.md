## 一、阶段目标

把官方 `miniprogram-ts-sass-quickstart` 模板改造成本项目的目标形态——**JS + SCSS + WebView 渲染 + TDesign**，得到一份干净、能长期开发的骨架，不写任何业务代码。

达标标志：

- 工程里没有任何 `.ts` 页面/组件文件，没有 Skyline 相关配置；
- `global.scss` 中的变量能在任意 `.scss` 里直接使用；
- `tabBar` 四个页面可互跳；
- 有 `.gitignore` 与阶段化提交习惯。

## 二、知识点讲解

### 2.1 小程序不是网页：双线程模型

```
逻辑层（JS 引擎：iOS = JavaScriptCore，Android = V8）
   │   你写的 .js：Page({ data })、事件处理、wx.request
   │            ↑↓  唯一通道 setData()，数据要序列化后跨线程传递
渲染层（WebView）
   │   WXML + WXSS 编译成 HTML/CSS，负责把 data 画出来
```

三条推论，后面每个阶段都会用到：

| 推论 | 说明 | 后续影响 |
|---|---|---|
| `setData` 是跨线程通信，不是变量赋值 | 每次调用都要序列化数据、发消息、等渲染层接收 | S6 购物车只 setData 变化字段；长列表分页只追加不重设 |
| 逻辑层拿不到 DOM | 没有 `document` / `querySelector` | 想改界面只能改 `data`，所以「数据驱动」是小程序唯一范式 |
| 渲染层与逻辑层可能不同步 | `setData` 是异步的，回调里才是渲染完成 | 需要拿节点尺寸用 `wx.createSelectorQuery()`，不能立即读 |

### 2.2 渲染引擎的两代：WebView 与 Skyline

| | WebView 渲染（旧，默认） | Skyline 渲染（新，2022 起 / 基础库 3.0+） |
|---|---|---|
| 原理 | 每页一个 WebView，WXML/WXSS → HTML/CSS | 自绘渲染，逻辑层直接产出渲染指令，不用 WebView（思路近 Flutter） |
| 组件框架 | exparser（默认） | 必须配 `glass-easel` |
| 优势 | 兼容性最好、生态完整、可用 Chrome DevTools 调 DOM | 帧率高、内存低、支持手势系统与 worklet 动画 |
| 劣势 | 长列表/复杂动画易掉帧 | 组件库基本未适配；不支持 `web-view` 组件与部分 CSS；无法用 DOM 调试 |
| 市面采用 | **绝大多数项目**：所有教程、TDesign、Vant Weapp 都基于它 | 官方自家产品与性能敏感场景为主 |

**结论**：本项目选 WebView。三个理由：① 零基础需要可搜索的环境；② TDesign 基于 WebView 实现；③ 商城的瓶颈在接口与图片，不在渲染帧率。

> 模板默认把 Skyline 打开了（`skylineRenderEnable: true` + `rendererOptions` + `glass-easel`），所以 S0-1 的第一件事就是把它拆掉。

### 2.3 一个页面 = 四件套 + 一条注册

| 文件 | 作用 | 备注 |
|---|---|---|
| `index.js` | 逻辑：`Page({ data, 生命周期, 事件处理 })` | 逻辑层 |
| `index.json` | 页面配置：`usingComponents`、是否允许下拉刷新等 | 只对本页生效 |
| `index.wxml` | 结构：标签 + 数据绑定 `{{}}` | ≈ HTML，但只能用小程序组件 |
| `index.scss` | 样式：支持嵌套与变量，单位用 `rpx` | 编译产物是 WXSS |

页面必须在 `app.json` 的 `pages` 数组里注册，**路径不带后缀**（写 `pages/index/index`，不是 `pages/index/index.js`）。这就是为什么把 `.ts` 改名成 `.js` 时，`app.json` 一个字都不用动。

### 2.4 编译插件：`useCompilerPlugins`

`project.config.json` 里的 `useCompilerPlugins` 是**开发者工具内置的转译器开关**，不是项目依赖：

- `"typescript"`：把 `.ts` 转成 `.js`；
- `"sass"`：把 `.scss` 转成 `.wxss`。

关掉 `typescript` 后，`.ts` 文件不再被编译——所以 `S0-1` 必须把 `.ts` 全删干净，否则会残留「看不见但存在」的文件。保留 `sass`，因为它同时负责把 `global.scss` 注入每个 scss 文件（`sassSetting.scssCommonUseFilePath`）。

### 2.5 为什么小程序要「构建 npm」（S0-2 会实操）

小程序的运行环境没有 Node 的模块解析，`require('tdesign-miniprogram/button')` 在真机上找不到 `node_modules`。所以开发者工具提供了「构建 npm」：把 `node_modules` 里用到的包**拷贝并按小程序规则改写**到 `miniprogram_npm/`，页面才 import 得到。这也是 `miniprogram_npm/` 要进 `.gitignore` 的原因（它是由 `package.json` 派生的产物）。

## 四、S0-1 实操记录

### 4.1 改配置（两处开关必须同时关）

`project.config.json`：

```diff
  "useCompilerPlugins": [
-   "typescript",
    "sass"
  ],
- "skylineRenderEnable": true,
+ "skylineRenderEnable": false,
```

`app.json`：

```diff
- "rendererOptions": {
-   "skyline": { "defaultDisplayBlock": true, "defaultContentBox": true, ... }
- },
- "componentFramework": "glass-easel",
  "style": "v2",
```

> 为什么要关两处：`project.config.json` 管「工具是否启用 Skyline」，`app.json` 管「页面用什么渲染」。只关一个会出现「改了没生效」的假象。

### 4.2 TS → JS（5 个文件，只去类型，不改逻辑）

| 原文件 | 现文件 | 去掉的标注 |
|---|---|---|
| `app.ts` | `app.js` | `App<IAppOption>({` → `App({` |
| `pages/index/index.ts` | `pages/index/index.js` | `getApp<IAppOption>()`、`(e: any)` ×2 |
| `pages/logs/logs.ts` | 已删除 | — |
| `components/navigation-bar/navigation-bar.ts` | `navigation-bar.js` | `_showChange(show: boolean)` |
| `utils/util.ts` | `utils/util.js` | `(date: Date)`、`(n: number)` |

### 4.3 清理模板残留

| 处理 | 原因 |
|---|---|
| 删除 `pages/logs/` 四件套并从 `app.json` 的 `pages` 移除 | quickstart 的「演示页」，只用来打印启动日志，无业务价值 |
| 重写 `pages/index/*` 为占位页 | 原页是「获取头像昵称」演示，`wx.getUserProfile` 已废弃，S2 整页重写；先留最小可编译骨架 |
| 删除空目录 `mock/`、`packageGoods/`、`components/goods-item`、`components/page-status`、`components/price` | 早期误建的空壳；git 不跟踪空目录，真正需要时随代码一起创建 |
| 保留 `components/navigation-bar/` | 自定义导航栏会用（`app.json` 已设 `navigationStyle: custom`），S2 改造 |
| 保留 `typings/`、`tsconfig.json` | 编辑器提示 + 未来迁移 TS 的地基，不参与编译 |
| 保留 `utils/util.js` 的 `formatTime` | S7 订单时间展示要用 |
| 保留 `sitemap.json` | `app.json` 的 `sitemapLocation` 指向它 |

### 4.4 新建 `global.scss`

由 `project.config.json` 的 `sassSetting.scssCommonUseFilePath: "global.scss"` 指定，工具会把它**自动注入每个 scss 文件顶部**。

铁律：**只放变量和 mixin，不写选择器**，否则每个 scss 编译都会重复输出一遍，样式体积成倍增长。

当前包含：品牌色（`$brand-color`）、文字色、背景/边框色、字号（`$font-xs ~ $font-xl`）、间距、圆角，以及 `ellipsis` / `ellipsis-multi` / `hairline` 三个 mixin。

### 4.5 `app.scss` 全局重置

WebView 渲染下默认盒模型是 `content-box`，`width: 100%` 加上内边距会溢出。所以在 `app.scss` 统一给常用标签加 `box-sizing: border-box`，并设置 `page` 的底色与基础字号。

> 注意：`app.scss` 里故意没写 SCSS 变量——先保证编译一定通过，变量注入这件事放到 S0-3 单独验证。

### 4.6 顺手修掉的废弃 API

`navigation-bar.js` 原用 `wx.getSystemInfo`（已废弃），改为：

```js
const windowInfo = wx.getWindowInfo()   // windowWidth / safeArea
const deviceInfo = wx.getDeviceInfo()   // platform
```

## 五、新旧写法对照（零基础必看）

| 场景 | 旧写法（老教程常见） | 现行推荐 | 说明 |
|---|---|---|---|
| 渲染引擎 | `rendererOptions` + `glass-easel` | 默认 WebView，不加任何渲染配置 | Skyline 是可选优化，不是默认 |
| 获取用户头像昵称 | `wx.getUserProfile` | `<button open-type="chooseAvatar">` + `<input type="nickname">` | 前者 2022 年起被收回，只能拿到匿名信息 |
| 获取系统信息 | `wx.getSystemInfo` / `getSystemInfoSync` | `wx.getWindowInfo` / `wx.getDeviceInfo` / `wx.getAppBaseInfo` | 拆分后单次调用更轻，且各端一致 |
| 更新对象字段 | `setData({ userInfo: {...this.data.userInfo, x} })` | `setData({ 'userInfo.x': v })` | 前者序列化整个对象，后者只传变化路径 |
| 模块引入 | `const util = require('../../utils/util.js')` | `import { formatTime } from '../../utils/util'` | 小程序支持 ESM，编译期转 CommonJS；**路径不写后缀** |
| 样式单位 | `px` | `rpx`（750rpx = 屏幕宽） | rpx 按屏宽等比缩放，适配成本最低 |
| 页面注册 | 认为改文件名要改 `app.json` | `app.json` 只写路径不带后缀 | 改后缀不影响路由 |

## 七、踩坑与复盘

| 现象 | 原因 | 处理 |
|---|---|---|
| 配置改完仍按 Skyline 渲染 | 只关了 `project.config.json`，`app.json` 的 `rendererOptions` 还在 | 两处都关 |
| `app.json` 报配置解析失败，但没指出哪错 | JSON 不允许尾随逗号，工具提示很含糊 | 删完字段把 `}` 前面多余的逗号一并删掉 |
| `.ts` 和 `.js` 同名共存 | 手动「新建文件」而非「重命名」 | 删掉 `.ts`，只保留 `.js` |
| 删掉页面后编译报「未找到页面」 | `app.json` 的 `pages` 还留着该路径 | 同步删 `pages` 里的条目 |
| 页面里 `import` 报找不到模块 | 写了 `.js` 后缀 | 小程序路径不带后缀 |

### 复盘

- 模板自带的「默认技术栈」不等于「我们的技术栈」——选型要显式确认，落在 `00-plan.md` 2.1 节。
- 空目录在 git 里无法保存，所以目录结构要靠「随代码一起创建」，不要提前建空壳。
