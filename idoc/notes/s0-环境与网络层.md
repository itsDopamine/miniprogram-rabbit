## 2. 接口实测结论（Node 直连，非小程序环境）

| 验证项 | 结果 |
| --- | --- |
| `GET /home/banner?distributionSite=1` | HTTP 200；返回 `{ code: "1", msg: "操作成功", result: [...] }` |
| 成功码 | **`code` 是字符串 `"1"`**，不是数字 0；封装层不依赖 code，页面只取 `result` |
| 图片地址 | 接口返回 `http://yjy-xiaotuxian-dev.oss-cn-beijing.aliyuncs.com/...`；同域名 HTTPS 返回 200，已统一转 https |
| `POST /login`（测试账号） | HTTP 200；`code: "1"`；`result.token` 长约 219 字符 |
| `GET /member/cart` 无 token | HTTP 401，body：`{"message":"token校验失败","msg":"token校验失败","code":"10019"}` |
| `GET /member/cart` + 裸 token | HTTP 200，正常返回购物车 |
| `GET /member/cart` + `Bearer <token>` | HTTP 200，也正常返回 |
| 结论 | `Authorization` 直接用 token 即可（与文档示例一致）；服务端也兼容 Bearer，不需要改 `request.js` |

> 临时 token 文件验证后已删除，仓库内不保留任何凭证。

## 3. 网络层设计要点

1. `utils/request.js` 是全项目唯一 `wx.request` 入口；页面只 `require('../utils/request')`。
2. 默认 header 带 `source-client: miniapp`；有 token 才带 `Authorization`。
3. HTTP 401：登录接口自身不触发全局跳转；其他接口 1.5s 内只跳一次登录页（单飞锁）。
4. 业务成功与否先不拦截，原样返回 `{ code, msg, result }`，页面取 `result`；等 S2 全量核对后再决定是否统一判 code。
5. `loading` 用计数管理，并发请求不会提前关闭。
6. 超时 10s；失败统一 toast，可用 `silent` 关闭。
7. 图片协议统一在 `utils/format.js#normalizeImageUrl` 归一为 https。

## 6. S0 三问自答（用自己的话复述）

1. **`app.json` / 页面 `json` / `project.config.json` 各管什么？**
   `app.json` 管全局路由、窗口、tabBar、分包与渲染后端；页面 `json` 管单页标题、下拉刷新、组件引用；`project.config.json` 是开发者工具的工程配置（编译插件、ES6、Skyline 开关、appid），不参与运行时。
2. **`App.onLaunch` 与 `Page.onLoad` 的顺序？`globalData` 适合放什么？**
   先 `App.onLaunch`（全局只一次），再目标页 `onLoad`。`globalData` 适合放「当前会话内的轻量共享状态」（用户信息缓存、待传递的分类 id），不适合放需要持久化的 token/购物车（storage 为准）。
3. **`wx.request` 的 `success` 在 HTTP 500 时触发吗？`statusCode` 与业务 `code` 的区别？**
   触发，只要拿到 HTTP 响应就会进 `success`。`statusCode` 是 HTTP 层状态；`code` 是业务层（本项目成功是字符串 `"1"`，401 时 `code` 为 `"10019"`）。判断「请求是否成功」先看 `statusCode`，判断「业务是否成功」再看 `code`。
