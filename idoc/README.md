# idoc 文档索引

本目录存放本项目的技术方案、学习手册与推进记录。临时文件统一放 `idoc/tmp/`（用完即删，已在 `.gitignore` 中忽略）。

| 文档 | 作用 | 维护方式 |
|---|---|---|
| [`00-plan.md`](./00-plan.md) | **总计划**：技术栈、工程现状、S0–S8 阶段总览、44 个接口与页面/阶段的映射、风险与待确认项 | 阶段目标变化时更新；每阶段完成后回填第 7 节推进记录 |
| [`stages/S0.md`](./stages/S0.md) | **S0 阶段手册**：配置迁移与工程骨架（原理讲解 + 逐文件改动 + 验收 + 坑） | 本阶段新增知识点、踩坑、结论随时补写 |
| `stages/S1.md` … `stages/S8.md` | 后续每个阶段一份同构手册 | 进入该阶段时创建 |

## 阶段手册统一结构

每份 `stages/S{N}.md` 保持同一骨架，方便回查与复习：

1. **阶段目标** —— 一句话说明这段学完能做什么
2. **知识点讲解** —— 原理层：为什么这样设计、和 Web/React 的差异
3. **任务清单** —— 任务号 / 内容 / 状态
4. **实操记录** —— 实际改动（改前 → 改后）、关键代码片段
5. **新旧写法对照** —— 市面上旧做法 vs 现行推荐做法
6. **验收清单** —— 可勾选的行为验证
7. **踩坑与复盘** —— 实际遇到的问题及结论

## 约定

- 文档只写「结论 + 可复查的细节」，不贴整页代码；代码在 `miniprogram/` 里。
- 接口字段级细节一律以 Apifox 为准，不确定就在 `00-plan.md` 第 6 节登记。
- 对话里只做结论补充与提醒，**细节以文档为准**。
